One important design decision I made was to separate the agent’s capabilities based on their specific purposes. I used Knowledge Base retrieval to handle policy and product-related questions, backend tools to perform order and refund operations, and a dedicated calculator to calculate loyalty discounts. By assigning different responsibilities to each tool, I aimed to make the agent’s behavior more structured and predictable. This approach also helped reduce the possibility of the agent selecting an inappropriate tool when responding to user requests. Overall, I believe this separation of responsibilities is important for maintaining clarity and consistency in the agent’s operations.

One of the main challenges I encountered was handling the response structure from the Knowledge Base. Initially, the search returned empty results because the retrieved text was nested deeper within the response payload than I had expected. To resolve this issue, I inspected the actual response structure and modified the parsing logic using chained `.get()` calls to safely access the required text. Another challenge involved the Lambda/API integration, where incoming requests contained missing or empty fields. After investigating the issue, I corrected the proxy integration configuration to ensure that request data could be passed properly. These challenges helped me understand the importance of examining data structures and verifying configurations when integrating different services.

For production deployment, my main considerations would be scalability, reliability, and proper user memory isolation. As the number of concurrent users increases, the agent should be able to maintain consistent performance without affecting the quality of its responses. Additionally, each user's memory and conversation context must remain isolated to prevent information from being mixed between different users. I would also pay close attention to the accuracy of information retrieved from tools and stored context, particularly when handling order and refund requests. These considerations are essential for ensuring that the agent remains dependable and provides accurate responses in a real-world environment.
